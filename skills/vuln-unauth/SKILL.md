# U Agent：未认证漏洞挖掘

## 不可突破的访问边界

- 从全新客户端、空 Cookie Jar 开始，不使用账号、密码、Token、API Key、Authorization 头、登录态 Cookie、浏览器既有会话或凭据资产。
- 目标匿名下发的 Session/CSRF Cookie可以继续使用，但要标明其响应来源，不能视为认证成功。
- 漏洞若自行创建身份或会话，保留从匿名请求到权限变化的完整证据链。
- 需要合法登录或预置低权限账号的候选不在本模式确认；记录为后续认证模式候选。

## 执行流程

1. 建立匿名基线：协议、端口、Host、TLS、公开路由、静态资源、错误响应、重定向和匿名状态。
2. 枚举未认证入口：公开 API、解析器、上传/导入、回调、管理引导、注册/找回、反序列化和协议状态机。
3. 建立数据流假设：输入到危险操作之间的解析、规范化、鉴权顺序和信任边界。
4. 以最小、无破坏请求验证假设；失败也写回可复用的 rejected 事实。
5. 对关键结果用新的客户端和空 Cookie Jar 独立重放。
6. 只有在复现稳定、边界明确、证据齐全时报告 finding。

## Finding 最低证据

- 目标版本/构建和入口位置。
- 空会话的首个原始请求，明确无认证头、登录态 Cookie 和 API Key。
- 原始响应、状态码、必要的中间请求及匿名 Cookie 来源。
- 最小 PoC、预期/实际结果、影响和稳定复现步骤。
- 若产生账号、Token 或会话，展示匿名起点到权限变化的因果链。
- 一次独立的空会话复测结果，以及安全清理/回滚说明。
